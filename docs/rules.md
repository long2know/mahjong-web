# Changsha rules evidence — `changsha-v1`

`changsha-v1` is the sole profile for [the host boundary](architecture.md#rules--host-boundary). It follows the single-bird, single-rolled-replacement profile documented by [Tencent QQ Game][qq], with the specific interpretations below. This is a playable, source-based profile, not a reconstruction certified by video or a claim that all Changsha tables agree.

## Evidence and executable defaults

Public sources checked 2026-11-19: Tencent's original Chinese help was decoded from its published GB encoding. [MahjongPros][pros] is a separate English guide and has internally conflicting single/multiple-winner advice. The [English Baike entry][baike] and [its `#2` URL][baike-2] are one AI-assisted translation, **not** independent confirmation. The [Reddit thread][reddit] was gated on direct access; only public indexed excerpts were used, at lower confidence. [The Mahjong Project][project] (“Sequences”, “Playing Out of Turn”, “Winning the Hand”) is a glossary/reference for shared mechanics, not evidence for Changsha scoring, eyes, winds, or match length.

## Reducer, projections, and verification

- [`Contracts.cs`][contracts] is the typed boundary for [protocol v1 snapshots][wire]. The host supplies clock and adds room/match/revision metadata, totals, and the display deadline. DTOs already supply phase/option/meld strings in wire casing. `PublicMeld.Method` is null for `chi`/`peng`; `gang`/`bu` make it `open`, `concealed`, or `added`. A concealed meld projects four null faces in `PublicSeat.Melds` in every phase. A terminal `PublicWinner.WinningHand` reveals only that winner's held faces and complete melds; `WinningTiles` contains the separate event tile. `WinPattern.Points` is an unadjusted unit; `Settlement.Transfers` is the authoritative positive `{fromSeat,toSeat,points,reason}` ledger (`win` or `opening`), matching `SeatResults.Delta` exactly. Closed responses, stock, non-winning hidden hands (apart from opening evidence), RNG input and physical tile IDs never appear on the wire.
- [`GameState`][checkpoint] is a server-private immutable checkpoint (System.Text.Json); `CheckpointVersion = 1`, including the persisted pending choices and turn kinds, and `ShuffleVersion = 1`. There is no separate engine event journal: `Choose`/`Expire` are the v1 transition inputs, not snapshots. The HMAC-SHA256 Fisher–Yates stream uses the 128-bit seed in little-endian order and rejection sampling. Independent HMAC domains bind window/option IDs to hand and sequence, options also to seat, and private tile IDs to hand and seat rather than wall position. Dice are derived separately from the completed decision's sequence, not from response order. Host keeps seeds private and namespaces wire windows across rematches.
- Choices close **at** their deadline. Only `Expire` makes progress on time alone, passing optional choices or discarding the drawn tile (otherwise the first legal discard) at the stored cutoff; an overdue restart doesn't reset the next deadline. Opening/rob/discard claim windows open only when at least one seat can respond. The last-tile draw/pass offer has `phase: "turn"`, `reason: "lastTile"` and the claim limit; private draws never add a public trigger. Bots pick only from the same options available through `PublicView` and the bot's own `SeatView`.
- Verified on SDK `10.0.404`/runtime `10.0.15` with `dotnet test tests/Mahjong.Rules.Tests -c Release -p:RestoreLockedMode=true`: **58 passed**, including successor-only Chow, winning-hand disclosure and committed dice. In the earlier qualification, the boundary and near-miss fixtures failed as expected when an isolated copy accepted a choice at the cutoff and treated rank 4 as a general. The four series below played four actual reducer hands each, then replayed every action and settlement exactly with repeated checkpoint reloads. Additional forced physical-deck fixtures exercise four consecutive kongs and rare terminal paths.
